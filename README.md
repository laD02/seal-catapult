# Seal Catapult (Hải Cẩu Bay) — code name SealCatapult

Unity 6.3 LTS (`6000.3.28f1`) · URP 2D · Android only (Google Play) · **landscape** (both ways up; the orientation is set in
`ProjectBuilder.ConfigurePlayer`, UI reference 1920×1080). Design: [GAME_DESIGN.md](GAME_DESIGN.md).

## Open & play in the Editor

1. Unity Hub → Add project from disk → this folder.
2. Open `Assets/Scenes/Boot.unity` → Play. (Any scene can be played directly.)
3. Controls in the Editor: Space / click = launch & dive, ← → = steer (Fin Steer), Esc = pause. Set the Game view to 16:9
   (or 4:3 to check the narrowest supported screen).

## Menu: Seal Catapult

- **2. Build Project** – sprite import settings (Android: ASTC, paintings 6×6, sprites/UI 4×4), TMP font, data assets
  (upgrade prices are rewritten from code), scenes. Keeps edited level data. It rewrites the four scene files with new
  fileIDs only: `git checkout -- Assets/Scenes` unless a scene really changed.
- **Rebuild Levels** – rewrites `Level_XX.asset` from `LevelDesigns.cs` (overwrites Inspector edits).
- **3. Build Android APK (test)** – `Builds/Android/SealCatapult.apk`, debug-signed, for sideloading.
- **4. Build Android AAB (Play Store)** – `Builds/Android/SealCatapult.aab`, needs a keystore (below).

Command line (Editor closed):

```sh
U=/Applications/Unity/Hub/Editor/6000.3.28f1/Unity.app/Contents/MacOS/Unity
$U -batchmode -quit -projectPath . -buildTarget Android -executeMethod SealCatapult.EditorTools.ProjectBuilder.BuildApk -logFile Logs/android.log
$U -batchmode -projectPath . -runTests -testPlatform EditMode -testResults "$PWD/Logs/tests.xml"
$U -batchmode -projectPath . -runTests -testPlatform PlayMode -testResults "$PWD/Logs/play.xml"
```

## QA on the emulator

The game is landscape: `adb shell settings put system user_rotation 1` after boot. `adb exec-out screencap` gives a black
frame for this build (Vulkan surface); capture through the emulator console instead:
`adb emu screenrecord screenshot <dir>` (saves a portrait PNG, rotate it 90°). `Pixel_PlayStore_34` is nearly full with
other projects' apps, so installs fail with `INSTALL_FAILED_INSUFFICIENT_STORAGE`; QA uses the fresh AVD `Pixel_QA_34`
(create with `avdmanager create avd -n Pixel_QA_34 -k "system-images;android-34;google_apis_playstore;arm64-v8a" -d pixel_3a`).

**Ads and consent in QA:** the QA APK (development build) uses Google's test ad units and asks UMP to act as an EU
player (`ConsentDebugSettings.DebugGeography = EEA` in `AdMob.TryConsent`), so the GDPR form and the Settings "Privacy"
button show on the emulator; `adb shell pm clear com.sealcatapult.game` asks again. Release builds use the real location.
Unity's batch build restarts adb: if the emulator shows `offline` afterwards, `adb kill-server; adb start-server`.
Emulator gotchas (2026-11-14): after the emulator hangs and dies (QEMU "hanging thread", exit 139) the next boot comes
from an older snapshot, so the game is gone: `monkey` says "No activities found" → `adb install -r` again. Right after
boot Android may kill the game with `stop com.google.android.gms due to start failure` (Play Services not up yet, not a
game crash; `adb logcat -b crash` stays empty): wait ~20 s and launch again.

**Reaching later levels in QA:** build the debuggable QA APK
(`-executeMethod SealCatapult.EditorTools.ProjectBuilder.BuildApkQa` → `Builds/Android/SealCatapult-qa.apk`, never upload
it), launch it once, stop it, then push a save: `adb push save.json /sdcard/Android/data/com.sealcatapult.game/files/save.json`
(Unity's persistentDataPath on Android is the external files dir, not `files/` under run-as). A level unlocks when the
one before it has ≥ 1 star, e.g. `"stars":[3,3,3,3,0,3,3,0,3,3,3,0]` opens 5, 8 and 12.

**Driving a level with `adb` (learned 2026-11-21):** blind `input tap` at a fixed gap only works at some rhythms: on
`Pixel_QA_34` a tap every 1.6 s got 2-3 pups out of the pit, 1.0, 1.5 and 2.2 s got none. In the arena one tap about
0.4 s after a pup glides in won level 1. A card that is gone after the next tap is the mission card; one that stays is
the result card. Frost Bay's first boss is level 12, not 10 (the hand-made levels; later castles: every tenth).

**Seeing the save notices:** stop the game, back up `…/files/save.json`, then for "could not save" make a directory
where the temp file goes (`adb shell mkdir /sdcard/Android/data/com.sealcatapult.game/files/save.json.tmp`), launch, open
and close Settings; for "save was damaged" write `{ not json` into `save.json` and launch (the game starts fresh and
keeps `save.json.corrupt`). Remove the directory or restore the backup afterwards.

**Other screen shapes on one emulator:** `adb shell wm size 1200x1600` (4:3) or `1080x2400` (20:9), relaunch the game,
`adb shell wm size reset` when done.

**Castle scenery for both phases:** per world `<w>` put three ChatGPT pictures in `Assets/Art/Reference`:
`pit_<w>.png` (an edit of `pit_bg_wide5.png` that keeps every outline, 1672×941; the colliders are measured on the
original), `arena_sky_<w>.png` (same composition as `arena_sky.png`) and `wall_<w>.png` (an edit of
`pit_side_walls_box.png`). `python3 -I Tools/prep_backgrounds.py` writes `bg_pit_<w>`, `bg_arena_sky_<w>` and
`rock_cobble_<w>` to `Resources/Art`; `WorldTheme.Scene` picks them, a missing one falls back to the Frost Bay art tinted.

**World maps (one per castle, 10 castles):** every map has exactly ONE road, no fork, no dead end. ChatGPT left to
design the road itself always paints a fork, so the road is designed here and ChatGPT only paints it:
1. `python3 Tools/map_plan.py <dir>` draws `plan_<world>.png`: grey land, one black road (spline through the points in
   `P`), brown bridges, S = village, F = fortress. Keep far-apart passes of the road ≥ 250 px apart (the tool prints
   `closest`), or ChatGPT merges them into a junction.
2. In ChatGPT attach `Assets/Art/Reference/map_world.png` (style) + the plan and ask it to paint the world along the
   plan with small pure-red dots on the road centre; nothing else in the picture pure red (bridges, banners, lava).
   After step 4, `python3 Tools/map_reach.py` must print PASS too: every level stone of every castle can be seen and
   tapped on 4:3 through 21:9 (the map painting crops and pans; no stone under a button). Run it as well after moving
   a map button (`MapView.Build`, `UiKit.TopBar`) and keep the button boxes in the tool in step with the code.
3. `python3 Tools/map_roadcheck.py <image>` must print PASS (one chain of dots, 2 ends, no fork); then look at it too:
   village at one end, fortress gate at the other. On FAIL tell ChatGPT what is wrong and repaint.
4. Save as `Assets/Art/Reference/map_<world>_dots.png`, then
   `python3 -I Tools/map_trail.py canyon forest harbour caves volcano blossom palace tundra throne` (writes
   `Assets/Scripts/UI/MapTrails.cs`: the trails, the clean `map_<world>.png`, and `<World>Water`, the open-water points
   where the map's fish leap, for the worlds in `SEA`; a world's start/end are `ENDS` in the tool), then
   `python3 -I Tools/prep_backgrounds.py` copies `map_<world>.png` to `Resources/Art/map_bg_<world>.png`.

## Analytics (Firebase)

Firebase Analytics without the Firebase Unity SDK: `Assets/Scripts/Analytics/` (JNI), dependency
`Analytics/Editor/FirebaseDependencies.xml` (also written into `Assets/Plugins/Android/mainTemplate.gradle`), app ids in
`Assets/Plugins/Android/FirebaseConfig.androidlib/res/values/firebase.xml` (app id from the console's `google-services.json` for
this package; a new package needs a new app in Firebase and new ids there). The API key is the project's **Android key
created 2026-11-16** (Firebase APIs only, no app restriction): the `google-services.json` download offered One Line Fill's
key, which is restricted to `com.onelinefill.game` and made Firebase Installations answer 403 ACCESS_DENIED. Collection is off in the manifest and turned on
after ads consent. Check events live: `adb shell setprop debug.firebase.analytics.app <package>`, then Firebase console →
Analytics → DebugView.

## Ads (AdMob)

Rules: `GAME_DESIGN.md` §13b. Plugin: Google Mobile Ads Unity `com.google.ads.mobile` 11.6.0 from OpenUPM
(`Packages/manifest.json` scoped registry; brings Unity's External Dependency Manager). Code: `Assets/Scripts/Ads/`
(`AdPolicy` pure rules + EditMode tests, `AdMob` SDK calls, `AdsConfig` ids). The app id is written into
`Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings.asset` by `ProjectBuilder.ConfigurePlayer`; the plugin's
build step enables the custom gradle templates in `Assets/Plugins/Android` and adds `play-services-ads` there.
Debug/QA builds, emulators and every build not installed from Google Play (a sideloaded `SealCatapult.apk`) request
Google's **test** units; only a release build installed from Play uses the real units (`AdMob.UseTestUnits`). Ad content
is capped at PG (`MobileAds.SetRequestConfiguration`). Real ads can therefore only be confirmed on a build installed from
Play (internal testing); logcat prints `[SealCatapult] ads: test units` or `real units` with the installer name at start.
Phones without ASTC support (some old GPUs) decompress the textures at load: correct picture, more memory. The Editor never starts the SDK. Never tap real ads on your own phone (AdMob bans the account).

## Release on Google Play

1. Create an upload keystore once and **keep it and its passwords safe and out of git** (losing it blocks updates):
   ```sh
   keytool -genkeypair -v -keystore ~/seal-catapult-upload.keystore -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Build the AAB with the keystore passed through environment variables:
   ```sh
   export SEAL_KEYSTORE=~/seal-catapult-upload.keystore SEAL_KEY_ALIAS=upload
   export SEAL_KEYSTORE_PASS='…' SEAL_KEY_PASS='…'
   $U -batchmode -quit -projectPath . -buildTarget Android -executeMethod SealCatapult.EditorTools.ProjectBuilder.BuildAab -logFile Logs/aab.log
   ```
3. Every upload needs a new version code: bump `Version` / `VersionCode` at the top of `ProjectBuilder.ConfigurePlayer`
   for a release, or `export SEAL_VERSION_CODE=<n>` to rebuild the same version (Play refuses a code it has seen).
4. Play Console: create the app (package `com.sealcatapult.game`), upload the AAB to internal testing first.
